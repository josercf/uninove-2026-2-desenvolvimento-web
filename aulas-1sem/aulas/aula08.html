O padrão MVC: quem faz o quê [1]

MVC é uma separação de responsabilidades. Cada camada tem um trabalho só, e nenhuma invade o trabalho da outra. É o que permite trocar a tela sem mexer na regra, e trocar o banco sem mexer na tela.

Takeaway

Regra de ouro do módulo: Controller magro, View burra e Model dono da regra. Quando você começa a escrever if de negócio dentro do .cshtml, a separação já quebrou.

Este é o slide que sustenta o módulo inteiro. Acompanhe o ponto coral: ele é a requisição GET /Especialidades saindo do navegador e voltando como HTML.

Program.cs: os serviços e o pipeline [1]

Todo o ciclo do slide anterior está declarado neste arquivo, gerado na Aula 07. Antes do Build() registram-se serviços; depois dele, monta-se o pipeline.

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllersWithViews();   // serviço: liga o MVC na aplicação

var app = builder.Build();

app.UseHttpsRedirection();   // 1. manda o http para o https
app.UseRouting();            // 2. descobre qual rota casa com a URL pedida
app.UseAuthorization();      // 3. decide se o pedido pode seguir
app.MapStaticAssets();       // 4. serve css, js e imagens de wwwroot

app.MapControllerRoute(name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

app.Run();

A ordem das linhas é a ordem de execução. Mover UseRouting de lugar não é estilo: o middleware seguinte precisa do resultado do anterior.

Roteamento convencional: a URL decomposta [2]

Uma única linha de Program.cs descreve todas as URLs da aplicação. Leia cada segmento da URL como uma pergunta que a rota responde.

Takeaway

Nenhuma URL é declarada uma a uma. Você escreve o Controller e a action, e o endereço da tela nasce do nome que você escolheu. Trocar o nome da classe muda a URL do site.

Exercício curto: quem atende cada URL?

Cinco minutos, no caderno ou no editor. Com a rota padrão {controller=Home}/{action=Index}/{id?}, preencha as três colunas para cada URL.

URL pedidaControllerActionid
/???
/Especialidades???
/Especialidades/Details/2???
/Home/Sobre???

A regra a aplicar: o primeiro segmento é o Controller, o segundo é a action, o terceiro é o id. Segmento que não veio na URL assume o valor padrão declarado na rota, e {id?} pode simplesmente não existir.

Controllers e actions: a convenção que faz tudo funcionar [3]

Nada aqui é configurado em arquivo nenhum: o ASP.NET Core encontra a classe e o método pelo nome.

using Microsoft.AspNetCore.Mvc;

namespace ClinicaVida.Web.Controllers;

public class EspecialidadesController : Controller   // classe pública, sufixo Controller
{
    public IActionResult Index()                     // action: método público da classe
    {
        return View();                               // Views/Especialidades/Index.cshtml
    }
}

As quatro convenções

Arquivo em Controllers/; classe herdando de Controller; nome terminado em Controller; e a URL usa o nome sem esse sufixo.

O erro clássico da primeira aula

Criar Especialidades.cs, sem o sufixo, ou deixar a action private. Nos dois casos a rota não encontra nada e o navegador mostra 404, sem nenhum erro de compilação.

IActionResult: a action escolhe a resposta [3]

IActionResult é o contrato de retorno de uma action: "devolvo alguma resposta HTTP, e decido qual em tempo de execução". Estes são os quatro retornos do módulo.

RetornoO que chega ao navegadorQuando usar na Clínica Vida+
View()200 com o HTML da View de mesmo nomeMostrar a lista de especialidades
Content("texto")200 com texto puro, sem layoutConferir depressa se a rota chegou na action
NotFound()404, a página de recurso inexistenteO id pedido não existe na clínica
RedirectToAction("Index")302 e uma nova requisição do navegadorDepois de gravar, voltar para a lista
Takeaway

View() devolve HTML na mesma requisição; RedirectToAction devolve uma ordem para o navegador pedir de novo, em outra URL. Um muda a tela, o outro muda a barra de endereços.

08 IActionResult
11

Parâmetros: o que vem da rota e o que vem da query string [3]

Você não lê a URL manualmente. O ASP.NET Core casa o nome do parâmetro do método com o nome do segmento da rota ou da chave da query string, e converte o texto para o tipo declarado.

// GET /Especialidades/Details/3?nome=Cardiologia

public IActionResult Details(int id, string nome)
{
    ViewData["Id"] = id;       // veio do segmento {id?} da rota
    ViewData["Nome"] = nome;   // veio da query string, depois do ?

    return View();
}

O nome é o contrato. Se o parâmetro se chamasse codigo em vez de id, a rota não teria onde encaixar o 3 e o método receberia zero. Nome trocado não dá erro de compilação: dá comportamento errado silencioso.

Views Razor: C# e HTML no mesmo arquivo [4]

Um arquivo .cshtml é HTML comum até aparecer um @. A partir dele o Razor lê C#, e volta para HTML sozinho quando encontra a próxima tag. Todo esse código roda no servidor: o navegador recebe só o HTML final.

@{
    ViewData["Title"] = "Especialidades";   // bloco de código C#
}

<h1>Especialidades da Clínica Vida+</h1>

<p>Agenda atualizada em @DateTime.Now.ToString("dd/MM/yyyy").</p>

<p>E-mail: contato@@clinicavida.com.br</p>   <!-- @@ escapa o arroba literal -->

Expressão: @DateTime.Now

Avalia e escreve o resultado no HTML, já com escape automático contra injeção de código.

Bloco: @{ ... }

Executa C# sem escrever nada na tela. Serve para preparar valores antes da marcação.

Onde a View mora: a convenção de pastas [5]

return View() não recebe caminho nenhum, e mesmo assim acha o arquivo: o framework procura em Views/NomeDoController/NomeDaAction.cshtml e, se não achar, em Views/Shared/.

ClinicaVida.Web/
├── Controllers/
│   └── EspecialidadesController.cs     a action Index() devolve View()
└── Views/
    ├── _ViewStart.cshtml               roda antes de toda View: define o Layout
    ├── Shared/
    │   └── _Layout.cshtml              cabeçalho, menu e rodapé comuns
    └── Especialidades/                 a pasta tem o nome do Controller
        ├── Index.cshtml                <--- é esta que o framework encontra
        └── Details.cshtml

O underline não é decoração. Arquivos iniciados por _ não são páginas: são partes reaproveitadas por outras Views. O _ViewStart.cshtml é o motivo de o menu aparecer em toda tela sem você repetir uma linha.

08 Convenção de pastas das Views

ViewData e ViewBag: levar o dado até a View [5]

São dois nomes para o mesmo dicionário, que vive durante uma única requisição. É o transporte simples de hoje; na Aula 09 o dado passa a viajar tipado, como objeto.

No Controller

ViewData["Titulo"] = "Especialidades";
ViewBag.Total = 3;

Na View

<h1>@ViewData["Titulo"]</h1>
<p>@ViewBag.Total especialidades</p>

O preço da comodidade: não há verificação em tempo de compilação. ViewData["Titlo"], escrito errado, não acusa nada e imprime vazio na tela. É exatamente esse risco que o modelo tipado da Aula 09 elimina.

Takeaway

O dicionário morre no fim da requisição. Nada guardado em ViewData sobrevive ao próximo clique: persistir exige banco, e isso é o assunto das Aulas 11 e 12.

Quiz de fixação

Com a rota padrão {controller=Home}/{action=Index}/{id?}, qual método atende a URL /Especialidades/Details/3?
  • AO método Index do HomeController, porque a rota cai no padrão sempre que o primeiro segmento não corresponde a um Controller.
  • BO método Especialidades do DetailsController, recebendo id igual a 3 no terceiro segmento.
  • CO método Details do EspecialidadesController, recebendo id igual a 3 no terceiro segmento.
  • DNenhum, porque o roteamento convencional não aceita três segmentos sem uma rota específica declarada.

Laboratório, passo 4 de 6: a action Details

Ciclo 4, sozinho. Volte ao EspecialidadesController e acrescente a segunda action, que recebe o identificador pela rota e o nome pela query string.

public IActionResult Details(int id, string nome)
{
    if (id < 1 || id > 3)
    {
        return NotFound();      // 404: essa especialidade não existe na clínica
    }

    ViewData["Id"] = id;
    ViewData["Nome"] = nome;

    return View();
}

Teste os dois caminhos: /Especialidades/Details/2?nome=Pediatria responde, e /Especialidades/Details/99 devolve 404. A estrutura if usada aqui ganha tratamento formal na Aula 09.

As três ideias da semana

A URL não aponta mais para um arquivo, e sim para um método; a convenção de nomes é o que liga rota, Controller e View sem configuração; e o Controller coordena, sem desenhar tela nem guardar dado.

Prévia da Aula 09: hoje as três especialidades estão digitadas dentro do HTML da View. Acrescentar a quarta exige editar marcação, e nenhuma tela sabe contar quantas são. Na próxima aula elas viram objetos em uma coleção, com if, foreach, List<T> e LINQ, e a View passa a receber dado tipado do Controller.
