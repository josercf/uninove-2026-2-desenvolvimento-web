O _Layout.cshtml é a moldura de todas as telas [1]

A View não é a página inteira. Ela é o miolo. O restante, que é igual em todas as telas, mora num arquivo só, em Views/Shared/_Layout.cshtml.

18 O layout como moldura
6

Quem manda a View usar o layout [1]

Nenhuma das suas Views escreve Layout = ..., e mesmo assim todas aparecem dentro da moldura. Dois arquivos de convenção, em Views/, respondem por isso.

Views/_ViewStart.cshtml

@{
    Layout = "_Layout";
}

Roda antes de cada View da pasta e das subpastas. Não gera marcação nenhuma: só decide a moldura.

Views/_ViewImports.cshtml

@using ClinicaVida.Web
@using ClinicaVida.Web.Models
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers

Concentra os @using e liga os Tag Helpers. É por causa dele que asp-for e <partial> funcionam sem import em cada View.

Takeaway

Os dois arquivos valem para a pasta em que estão e para tudo abaixo dela. Uma View avulsa pode desligar a moldura com Layout = null, e é assim que se devolve um pedaço de HTML por AJAX, como na Aula 14.

18 ViewStart e ViewImports
7

Um buraco para o miolo, outros para as seções [1]

O @RenderBody() aparece uma única vez e recebe a View inteira. As seções são buracos nomeados, que cada View preenche se quiser, e servem para o que precisa sair do miolo: scripts no fim do corpo, por exemplo.

<!-- Views/Shared/_Layout.cshtml -->
<main class="container py-4">
    @RenderBody()
</main>
<script src="~/lib/bootstrap/dist/js/bootstrap.bundle.min.js"></script>
@await RenderSectionAsync("Scripts", required: false)

<!-- Views/Consultas/Agendar.cshtml, no fim do arquivo -->
@section Scripts {
    <partial name="_ValidationScriptsPartial" />
    <script src="~/js/agendamento-ajax.js"></script>
}
Takeaway

required: false significa "se a View não declarar a seção, siga em frente". Com required: true, toda View que esquecer a seção quebra em tempo de execução. É o mesmo bloco que a Aula 10 usou na validação e a Aula 14 no AJAX.

Partial View: um pedaço de marcação, muitos lugares [2]

O layout resolve o que é igual em toda tela. A Partial View resolve o que se repete em algumas telas, e que o layout não tem como conhecer.

18 Partial View, o conceito
9

Como chamar a Partial e como passar o modelo [2]

Duas formas para o mesmo resultado. O Tag Helper <partial> é a forma atual e a que se lê melhor no meio da marcação; Html.PartialAsync serve quando a chamada precisa estar dentro de um bloco de código C#.

@model IEnumerable<Medico>

<div class="row g-4">
    @foreach (var medico in Model)
    {
        <div class="col-12 col-md-6 col-lg-4">
            <partial name="_CardMedico" model="medico" />
        </div>
    }
</div>

@* A mesma chamada, na forma de método: *@
@await Html.PartialAsync("_CardMedico", medico)
Takeaway

A Partial não executa action nenhuma e não tem layout: ela recebe pronto o modelo que a View passou. Se o dado que ela precisa exibir não está na mão de quem chama, a Partial é a ferramenta errada.

Partial View ou View Component? [3]

 Partial ViewView Component
O que éMarcação reaproveitadaPedaço de tela com lógica própria
De onde vêm os dadosDe quem chama, pelo modeloDa própria classe, que busca o dado
Tem classe C#Não, só o .cshtmlSim, com InvokeAsync e injeção
Como se chama<partial name="_CardMedico" /><vc:consultas-de-hoje />
No caseCard de médico e linha de consultaContador de consultas do dia no menu

O teste que decide: se toda action da aplicação tiver que passar a mesma informação para a Partial funcionar, ela quer ser um View Component. Um contador no menu não pode obrigar 12 Controllers a buscarem o número de consultas de hoje.

O Bootstrap está no seu projeto desde a Aula 07

O dotnet new mvc já traz o Bootstrap 5 em wwwroot/lib/, servido do seu próprio projeto, sem depender de internet. Hoje você deixa de conviver com ele e passa a usá-lo.

<!-- Views/Shared/_Layout.cshtml, no head. A ORDEM decide quem vence: -->
<link rel="stylesheet" href="~/lib/bootstrap/dist/css/bootstrap.min.css" />
<link rel="stylesheet" href="~/css/site.css" asp-append-version="true" />

<!-- No fim do body. O bundle traz o Popper junto, e sem ele o menu -->
<!-- sanduíche e o modal não abrem: eles precisam de JavaScript.     -->
<script src="~/lib/bootstrap/dist/js/bootstrap.bundle.min.js"></script>
Takeaway

O site.css vem depois do bootstrap.min.css de propósito: é isso que permite ajustar o framework sem editar o arquivo dele. Nunca edite o bootstrap.min.css, porque a próxima atualização apaga a sua alteração.

Os pontos de quebra são as media queries da Aula 05 [4]

A escala do Bootstrap

PrefixoA partir de
nenhum0, é a regra base
sm576px
md768px
lg992px
xl1200px
xxl1400px

É a mesma ideia, com outro nome

/* Aula 05, escrito por você */
.form-grid { grid-template-columns: 1fr; }

@media (min-width: 768px) {
  .form-grid {
    grid-template-columns: repeat(2, 1fr);
  }
}

Vira class="col-12 col-md-6". Mesmo min-width, mesma ordem do mais estreito para o mais largo.

Takeaway

Todo prefixo vale daquela largura para cima. Por isso col-md-6 continua valendo no desktop, a menos que um col-lg-4 venha depois dele, e por isso não existe prefixo para celular: quem cuida do celular é a classe sem prefixo.

A identidade da clínica por cima do Bootstrap [6]

Aplicação com Bootstrap e sem customização tem a mesma cara de milhares de outras. A paleta que você fixou na Aula 04 continua mandando: o framework entra por baixo dela, em wwwroot/css/site.css.

:root {
  --vida-primaria: #0B6E75;   /* as mesmas variáveis da Aula 04 */
  --vida-destaque: #E4572E;

  --bs-body-bg:      #F4F7F6;       /* --vida-fundo  */
  --bs-body-color:   #1F2A30;       /* --vida-texto  */
  --bs-border-color: #D6E2E0;       /* --vida-borda  */
  --bs-primary-rgb:  11, 110, 117;  /* text-primary e bg-primary */
}

/* O .btn-primary traz a cor compilada dentro dele e ignora o
   --bs-primary. Quem manda no botão são as variáveis dele: */
.btn-primary {
  --bs-btn-bg:           var(--vida-primaria);
  --bs-btn-border-color: var(--vida-primaria);
  --bs-btn-hover-bg:     #095A60;
}

Quiz de fixação

Qual é o papel de @RenderBody() dentro do _Layout.cshtml?
  • A Marca o ponto onde o conteúdo específico de cada View é inserido dentro do layout compartilhado.
  • B Renderiza o menu de navegação compartilhado, que por isso não precisa ser repetido em cada View.
  • CImporta as folhas de estilo e os scripts do Bootstrap declarados no _ViewImports.cshtml.
  • D Executa a action do Controller correspondente à View atual, devolvendo o modelo já preenchido.

Laboratório, passo 6 de 6: as telas e as três larguras

Grid e componentes em todas as telas do projeto

  1. CRUD de paciente: table table-striped na listagem e row com col-12 col-md-6 nos formulários.

  4. Abra o DevTools, ative o modo dispositivo e confira em 360px, 768px e 1280px.
