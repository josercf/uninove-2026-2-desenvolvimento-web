De onde viemos: o agendamento em duas etapas da Aula 13

Você entregou o agendamento em duas etapas usando HttpContext.Session, mais o cookie com a unidade preferida da clínica. O fluxo funciona, e ele tem um custo que ninguém mediu ainda.

O que já funciona

  • Etapa 1 guarda especialidade e médico na sessão.
  • Etapa 2 recupera a sessão e grava a Consulta.
  • O acesso direto à etapa 2 é bloqueado.
  • A unidade preferida volta do cookie.

O que incomoda quem usa

  • Cada escolha do usuário exige um envio de formulário.
  • Cada envio devolve uma página inteira nova.
  • A tela pisca, e a rolagem volta para o topo.
  • Para saber os horários livres, é preciso avançar de tela.

A pergunta de hoje: dá para trocar um pedaço da página, buscando dados no servidor durante o uso, sem recarregar nada em volta? Dá, e essa técnica tem nome: AJAX.

O que "assíncrona" quer dizer, na linha do tempo

Assíncrono não é rápido. É não bloquear: a requisição parte, e a interface continua respondendo enquanto o dado não chegou.

JSON: o formato em que os dados viajam [2]

JSON é texto. Nasceu da sintaxe de objeto do JavaScript, mas é entendido por C#, Python, Java e por qualquer linguagem que você venha a usar.

[
  { "id": 3, "nome": "Dra. Helena Vasques", "crm": "SP-118240" },
  { "id": 7, "nome": "Dr. Rafael Nakano",   "crm": "SP-204915" }
]
JSON, o texto que trafegaObjeto JavaScript, o que existe na memória
Chave sempre entre aspas duplasChave sem aspas, na maior parte dos casos
Texto só com aspas duplasAspas simples, duplas ou crase, tanto faz
Seis tipos: texto, número, booleano, nulo, objeto e vetorTem também função, data, undefined
Takeaway

A ponte são dois métodos: JSON.parse(texto) vira objeto, e JSON.stringify(objeto) volta a ser texto. O fetch já faz o parse por você, no await resposta.json().

fetch: pedir dados ao servidor de dentro da página [1]

São dois await, e cada um espera uma coisa diferente: o primeiro espera os cabeçalhos da resposta chegarem, o segundo espera o corpo ser lido e convertido.

async function carregarMedicos(especialidadeId) {
  const url = `/Consultas/MedicosPorEspecialidade?especialidadeId=${especialidadeId}`;

  const resposta = await fetch(url);      // espera os cabeçalhos

  // 404 e 500 NÃO lançam erro no fetch: quem avisa é o resposta.ok
  if (!resposta.ok) {
    throw new Error(`O servidor respondeu ${resposta.status}`);
  }

  return await resposta.json();           // espera e converte o corpo
}

A armadilha mais comum: o fetch só rejeita quando a requisição não acontece, por rede fora do ar. Um 404 ou um 500 é uma resposta que chegou normalmente. Sem o if (!resposta.ok), o seu código trata uma página de erro como se fosse a lista de médicos.

Você já conhece async e await: eles vieram da Aula 12 [3]

A mesma ideia, em duas linguagens: marque o método com async, espere com await, e quem espera não fica preso. Muda o nome do que volta e quem é liberado durante a espera.

C#, no servidor, Aula 12

public async Task<IActionResult> Index()
{
    var lista = await _context.Pacientes
        .ToListAsync();

    return View(lista);
}

JavaScript, no navegador, hoje

async function listar() {
  const r = await fetch("/Consultas/" +
      "MedicosPorEspecialidade?especialidadeId=3");

  return await r.json();
}

No servidor: a action que devolve JSON em vez de HTML [4]

É o mesmo Controller, o mesmo ClinicaContext e a mesma consulta com LINQ da Aula 12. Muda só o final: Json(...) no lugar de View(...).

// Em Controllers/ConsultasController.cs
public async Task<JsonResult> MedicosPorEspecialidade(int especialidadeId)
{
    var medicos = await _context.Medicos
        .Where(m => m.EspecialidadeId == especialidadeId)
        .OrderBy(m => m.Nome)
        .Select(m => new { id = m.Id, nome = m.Nome, crm = m.Crm })
        .ToListAsync();

    return Json(medicos);   // ou: return Ok(medicos);
}

O Select não é enfeite. Devolver a entidade inteira entrega ao navegador tudo o que ela carrega, inclusive o que ninguém pediu, e ainda arrasta a Especialidade junto se ela estiver carregada. Escolha campo a campo o que sai: é a diferença entre expor um dado e publicar um cadastro.

Devolver JSON não é o mesmo que ter uma API REST

A confusão é natural e vale desfazer agora: as duas actions de hoje existem para servir a sua própria tela. Nada nelas foi pensado para outro sistema consumir.

Hoje, Aula 14: JSON de apoio à tela

  • Controller MVC comum, herdando de Controller.
  • Rota normal: /Consultas/HorariosDisponiveis.
  • Objeto anônimo montado no Select.
  • Só GET, e só o que a página precisa desenhar.

Aula 16: API REST de verdade

  • [ApiController] e ControllerBase.
  • Rota api/[controller], com recurso e verbo.
  • DTOs, classes escritas para o contrato público.
  • POST, PUT, DELETE, CreatedAtAction e códigos de status.

Fronteira desta aula: nenhum [ApiController], nenhuma rota api/..., nenhum DTO e nenhum CreatedAtAction aparecem hoje. Isso é o assunto inteiro da Aula 16, e a comparação vai começar exatamente por estas duas actions que você escreve agora.

No cliente: da resposta ao DOM, com o que você já sabe

addEventListener, querySelector e a árvore do DOM são a Aula 06 inteira. O que muda é a origem do dado: ele não estava na página, e chega do servidor durante o uso. Tudo em wwwroot/js/agendamento-ajax.js.

const especialidade = document.querySelector("#especialidadeId");
const medico = document.querySelector("#medicoId");

especialidade.addEventListener("change", async () => {
  medico.innerHTML = "<option>Carregando...</option>";
  const medicos = await carregarMedicos(especialidade.value);

  medico.innerHTML = "<option value=''>Selecione o médico</option>";
  for (const m of medicos) {
    const opcao = document.createElement("option");
    opcao.value = m.id;
    opcao.textContent = `${m.nome} (${m.crm})`;
    medico.appendChild(opcao);
  }
});
Takeaway

Uma requisição por escolha do usuário, e não por tecla digitada. change em uma lista suspensa é seguro; input em campo de texto dispara uma requisição por caractere.

Quiz de fixação

O que a action precisa retornar para que o fetch do navegador receba dados e não uma página inteira?
  • AView(), porque o navegador consegue extrair os dados do HTML devolvido e montar o objeto sozinho.
  • BJson(...) ou outro resultado cujo corpo seja JSON, que é o formato que o fetch converte em objeto.
  • CRedirectToAction, apontando para a action que carrega os dados e devolve a tela já preenchida.
  • DContent com o tipo text/html, entregando apenas o trecho de página que será inserido no DOM.

O que fica desta aula

O dado passou a chegar durante o uso

Na Aula 06 o JavaScript só mexia no que já estava na página. Agora ele busca no servidor, com a página de pé.

JSON é o idioma comum

O C# projeta com Select, o navegador converte com resposta.json(), e no meio trafega texto.

Assíncrono é não bloquear

O mesmo async e await da Aula 12, agora libertando a thread do navegador em vez da do servidor.

Uma chamada, quatro telas

Carregando, com dados, vazio e erro. Programar só a segunda é entregar uma tela que trava calada.

Prévia da Aula 15: abra a sua aplicação em uma janela anônima e vá direto para /Consultas. A agenda inteira da clínica abre, com nome de paciente e horário, sem ninguém perguntar quem é você. Na próxima aula o sistema passa a saber quem está do outro lado e o que essa pessoa pode ver.
