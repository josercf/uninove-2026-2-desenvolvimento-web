De onde viemos: a primeira tela da clínica, na Aula 08

Você entregou o EspecialidadesController com as actions Index e Details, as Views correspondentes em Views/Especialidades e a navegação funcionando. A requisição já percorre rota, Controller, action e View.

O que já está de pé

  • A rota {controller}/{action}/{id?} encontra a sua action.
  • A action devolve uma View, com ViewData ou ViewBag.
  • A View Razor mistura C# e HTML e chega ao navegador.

O problema que sobrou

  • As especialidades estão escritas à mão dentro da View, uma a uma, em <li>.
  • Dado escrito à mão não pode ser filtrado, contado nem reordenado.
  • Acrescentar um médico hoje significa editar HTML.

O que muda hoje: o dado sai da View e vira objeto em uma coleção, dentro do Model. O Controller decide o que entra na lista, e a View apenas percorre o que recebeu. Para isso, precisamos primeiro da linguagem: decisão, repetição, método, classe e coleção.

Decisão: if, else if e else [1]

A sintaxe é a mesma do JavaScript da Aula 06, com uma diferença que o compilador cobra: a condição precisa ser bool. Em C# não existe "valor que parece verdadeiro".

int hora = 14;                          // hora escolhida para a consulta
string turno;

if (hora < 7 || hora >= 19)
{
    turno = "Fora do expediente";       // a Vida+ atende das 07h às 19h
}
else if (hora < 12)
{
    turno = "Manhã";
}
else
{
    turno = "Tarde";
}
Takeaway

Quando a decisão só escolhe entre dois valores, o operador ternário resolve em uma linha: string saudacao = hora < 12 ? "Bom dia" : "Boa tarde";

Muitos caminhos: switch e a expressão switch [1]

Quando a decisão compara o mesmo valor com várias alternativas, uma escada de else if fica ilegível. A duração da consulta na Clínica Vida+ depende da especialidade.

switch (especialidade.Nome)               // switch clássico: escolhe um caminho
{
    case "Cardiologia": duracao = 40; break;
    case "Pediatria":   duracao = 30; break;
    default:            duracao = 20; break;
}

int duracao = especialidade.Nome switch   // a mesma decisão, devolvendo o valor
{
    "Cardiologia" => 40,
    "Pediatria"   => 30,
    _             => 20,
};

No switch clássico, o break não é enfeite: sem ele o compilador recusa o código. Na expressão switch, o _ é o caso padrão, e o compilador avisa se você deixar alguma possibilidade sem resposta.

Repetição: for, foreach, while [1]

O for quando você precisa do índice; o foreach quando só quer visitar cada item. A agenda do dia é um caso clássico dos dois.

string[] horarios = { "08:00", "09:00", "10:00", "11:00" };

for (int i = 0; i < horarios.Length; i++)     // sei quantas voltas vou dar
{
    Console.WriteLine($"{i + 1}o horário: {horarios[i]}");
}

foreach (string h in horarios)                // visito todos, sem índice
{
    if (h == "10:00") continue;               // pula este e segue o laço
    if (h == "11:00") break;                  // encerra o laço aqui
    Console.WriteLine(h);
}

Faltam dois: while testa antes e pode não executar nenhuma vez; do ... while executa ao menos uma vez e testa depois.

Métodos: dar nome a uma regra da clínica [1]

O que na Aula 06 era uma função solta, aqui é um método, sempre dentro de uma classe, com o tipo de retorno declarado antes do nome.

// modificador, tipo de retorno, nome e lista de parâmetros
public static string PeriodoDoDia(int hora)
{
    if (hora < 7 || hora >= 19) return "Fora do expediente";
    return hora < 12 ? "Manhã" : "Tarde";
}

// sobrecarga: mesmo nome, lista de parâmetros diferente
public static string PeriodoDoDia(TimeSpan horario)
{
    return PeriodoDoDia(horario.Hours);
}

Console.WriteLine(PeriodoDoDia(14));            // Tarde
Takeaway

A assinatura é o nome mais a lista de parâmetros. É por ela que o compilador escolhe a sobrecarga certa, ainda na compilação, e não em tempo de execução.

Classes e propriedades automáticas [1]

A classe é a forma; o objeto é cada exemplar criado a partir dela. Os Models da Clínica Vida+ moram em Models/, no namespace ClinicaVida.Web.Models.

namespace ClinicaVida.Web.Models;

public class Especialidade
{
    public int Id { get; set; }                          // propriedade automática
    public string Nome { get; set; } = string.Empty;
    public string Descricao { get; set; } = string.Empty;
}

// instanciação com inicializador de objeto
var cardio = new Especialidade { Id = 1, Nome = "Cardiologia" };
Console.WriteLine(cardio.Nome);                          // Cardiologia

{ get; set; } declara uma propriedade que lê e escreve, com o campo por trás gerado pelo compilador. O = string.Empty existe para o texto nascer vazio em vez de null, e é o que cala o aviso de referência nula do compilador.

O Model Medico e a ligação com a especialidade

Um médico pertence a uma especialidade. Essa ligação aparece duas vezes na classe, e as duas têm papéis diferentes.

namespace ClinicaVida.Web.Models;

public class Medico
{
    public int Id { get; set; }
    public string Nome { get; set; } = string.Empty;
    public string Crm { get; set; } = string.Empty;

    public int EspecialidadeId { get; set; }             // a chave: só um número
    public Especialidade? Especialidade { get; set; }    // o objeto inteiro
}
Takeaway

EspecialidadeId é o que você filtra e compara; Especialidade é o que você exibe. O ? avisa que o objeto pode estar ausente. Na Aula 11 esse par vira chave estrangeira e relacionamento no banco.

Array e List<T>: a coleção que cresce [2]

O array tem tamanho fixo, escolhido na criação. A List<T> cresce e encolhe, e é o que você vai usar em 99% dos casos. O T é o tipo que ela guarda, verificado pelo compilador.

string[] fixos = new string[3];        // tamanho definido na criação
fixos[0] = "08:00";

List<string> horarios = new();         // cresce e encolhe em execução
horarios.Add("08:00");
horarios.Add("09:00");
horarios.Add("10:00");
horarios.Remove("08:00");

Console.WriteLine(horarios.Count);     // 2
Console.WriteLine(horarios[0]);        // 09:00, indexação por posição

Dictionary<TKey, TValue>: busca por chave [2]

Quando o acesso é por um nome, e não por uma posição, o dicionário é a estrutura certa. Cada chave é única e leva direto ao valor, sem percorrer a coleção inteira.

var duracaoPorEspecialidade = new Dictionary<string, int>
{
    ["Cardiologia"]  = 40,
    ["Pediatria"]    = 30,
    ["Dermatologia"] = 25,
};

int minutos = duracaoPorEspecialidade["Pediatria"];        // 30

if (duracaoPorEspecialidade.TryGetValue("Neurologia", out int m))
{
    Console.WriteLine(m);        // não entra: essa chave não existe
}
Cuidado

Acessar uma chave inexistente com colchetes lança exceção e derruba a requisição. TryGetValue devolve false e segue a vida: prefira-o sempre que a chave puder não existir.

LINQ é um funil sobre a coleção [3]

Cada operador recebe uma sequência e devolve outra. Você encaixa um no outro e a coleção vai sendo estreitada e transformada até virar exatamente o que a tela precisa.

09 LINQ como um funil
15

Os seis operadores que resolvem o dia a dia [3]

O m => ... é uma expressão lambda: um método sem nome, escrito no lugar onde é usado. Leia como "para cada médico m, avalie isto".

List<Medico> medicos = ClinicaEmMemoria.Medicos;      // 6 médicos

medicos.Where(m => m.EspecialidadeId == 1);      // vários: 2 cardiologistas
medicos.OrderBy(m => m.Nome);                    // os 6, em ordem alfabética
medicos.Select(m => m.Nome);                     // 6 strings, não 6 médicos
medicos.FirstOrDefault(m => m.Crm == "41880");   // 1 médico ou null
medicos.Any(m => m.EspecialidadeId == 4);        // true ou false
medicos.Count(m => m.EspecialidadeId == 2);      // 2
Takeaway

Nenhum deles altera a lista original: cada um devolve uma nova sequência. E a consulta só é executada quando alguém percorre o resultado, num foreach ou num ToList().

O Controller decide, e entrega a coleção pronta [4]

O parâmetro especialidadeId chega da query string, como na Aula 08. Sendo int?, ele aceita ausência: sem filtro, a lista vai inteira.

public IActionResult Index(int? especialidadeId)
{
    var medicos = ClinicaEmMemoria.Medicos.AsEnumerable();

    if (especialidadeId is not null)
    {
        medicos = medicos.Where(m => m.EspecialidadeId == especialidadeId);
    }

    return View(medicos.OrderBy(m => m.Nome).ToList());   // a coleção vai à View
}
Takeaway

/Medicos devolve todos; /Medicos?especialidadeId=1 devolve só os cardiologistas. A View é a mesma nos dois casos: quem decide o conteúdo é o Controller.

A View tipada: @model e o foreach Razor [4]

A primeira linha do arquivo declara o que a View espera receber. A partir dela, Model é aquela coleção, com autocompletar e erro de compilação se você errar o nome de uma propriedade.

@model IEnumerable<Medico>

<h2>Corpo clínico</h2>

<ul>
@foreach (var medico in Model)
{
    <li>@medico.Nome, CRM @medico.Crm</li>
}
</ul>
Takeaway

Com ViewBag, errar o nome só quebra em execução, na cara do usuário. Com @model, quebra na compilação, na sua cara. O _ViewImports.cshtml gerado pelo template já traz @using ClinicaVida.Web.Models, por isso o nome curto Medico basta.

Quiz de fixação

O que a expressão medicos.Where(m => m.EspecialidadeId == 2) devolve?
  • AO primeiro médico cuja especialidade é a de identificador 2, ou nulo quando não houver nenhum.
  • BUma sequência com todos os médicos cuja EspecialidadeId é igual a 2, na ordem em que estão na lista.
  • CA quantidade de médicos da especialidade 2, como um número inteiro pronto para ser exibido na View.
  • DUm valor booleano indicando se existe pelo menos um médico cadastrado na especialidade de identificador 2.

Laboratório, passo 3 de 6: MedicosController e o filtro

Em Controllers/MedicosController.cs. O ViewBag leva a lista de especialidades para montar o campo de filtro; o Model leva os médicos.

public class MedicosController : Controller
{
    public IActionResult Index(int? especialidadeId)
    {
        var medicos = ClinicaEmMemoria.Medicos.AsEnumerable();

        if (especialidadeId is not null)
        {
            medicos = medicos.Where(m => m.EspecialidadeId == especialidadeId);
        }

        ViewBag.Especialidades = ClinicaEmMemoria.Especialidades;
        return View(medicos.OrderBy(m => m.Nome).ToList());
    }
}

Laboratório, passo 5 de 6: a action Details

Ciclo 4, sozinho. Um médico só, encontrado pelo id da rota, com a especialidade preenchida para exibir o nome dela em vez do número.

public IActionResult Details(int id)
{
    var medico = ClinicaEmMemoria.Medicos.FirstOrDefault(m => m.Id == id);
    if (medico is null) return NotFound();

    medico.Especialidade = ClinicaEmMemoria.Especialidades
        .FirstOrDefault(e => e.Id == medico.EspecialidadeId);

    return View(medico);      // Views/Medicos/Details.cshtml, @model Medico
}

Teste /Medicos/Details/999: precisa devolver 404, e não uma tela de erro. É o FirstOrDefault devolvendo null e o seu código tratando o caso.

Laboratório, passo 6 de 6: quantos médicos por especialidade

De volta ao EspecialidadesController da Aula 08. Um Dictionary guarda a contagem, e a tela de especialidades finalmente diz algo que a View não sabia calcular sozinha.

var contagem = new Dictionary<int, int>();

foreach (var e in ClinicaEmMemoria.Especialidades)
{
    contagem[e.Id] = ClinicaEmMemoria.Medicos.Count(m => m.EspecialidadeId == e.Id);
}

ViewBag.MedicosPorEspecialidade = contagem;
return View(ClinicaEmMemoria.Especialidades);   // @model IEnumerable<Especialidade>

Na View, cada especialidade vira um link para /Medicos?especialidadeId=@e.Id, com a contagem ao lado. Duas telas da clínica, ligadas pelo mesmo dado.
