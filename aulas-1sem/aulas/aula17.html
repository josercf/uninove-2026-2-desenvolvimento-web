De onde viemos: a API da Aula 16

Você entregou o ConsultasApiController com os cinco endpoints testados e documentados, protegido por [Authorize]. Ele funciona. E é exatamente por funcionar que a limitação fica visível.

Chave estrangeira e navegação: duas coisas diferentes

A chave estrangeira é o número que existe na tabela desde a Aula 11. A navegação é o objeto que o C# usa para chegar ao outro lado sem escrever nenhum WHERE.

public class Especialidade                 // lado 1: ganha a coleção
{
    public int Id { get; set; }
    public ICollection<Medico> Medicos { get; set; } = new List<Medico>();
}

public class Consulta                      // lado N: guarda as chaves
{
    public int PacienteId { get; set; }    // a chave estrangeira, desde a Aula 11
    public Paciente? Paciente { get; set; }  // a navegação, nova hoje
    public int MedicoId { get; set; }
    public Medico? Medico { get; set; }
}
Takeaway

Navegação nos dois sentidos significa poder ir de consulta.Paciente.Nome e também de paciente.Consultas.Count. Nenhuma propriedade antiga é renomeada: só acrescentamos.

Quando a convenção basta e quando é preciso a Fluent API [3]

O EF Core descobre sozinho o relacionamento quando a chave se chama <Entidade>Id. Ele não descobre o que você quer que aconteça na exclusão, nem duas navegações para a mesma entidade.

protected override void OnModelCreating(ModelBuilder builder)
{
    base.OnModelCreating(builder);   // obrigatório: o Identity mapeia as tabelas dele aqui

    builder.Entity<Medico>()
        .HasOne(m => m.Especialidade)      // deste lado, um
        .WithMany(e => e.Medicos)          // do outro lado, muitos
        .HasForeignKey(m => m.EspecialidadeId)
        .OnDelete(DeleteBehavior.Restrict);

    builder.Entity<Especialidade>().HasData(/* as quatro da Aula 11 */);
}

O base.OnModelCreating(builder) não é opcional desde a Aula 15: o ClinicaContext herda de IdentityDbContext<IdentityUser>, e é a chamada da base que mapeia as tabelas de usuário. Omitir a linha derruba o login.

Include e ThenInclude: dois níveis de distância [2]

A agenda do dia precisa da especialidade, que não está na Consulta nem no Medico: está na Especialidade, dois saltos adiante. ThenInclude continua o caminho a partir do último Include.

var agenda = await _context.Consultas
    .Include(c => c.Paciente)            // Consulta  ->  Paciente
    .Include(c => c.Medico)              // Consulta  ->  Medico
        .ThenInclude(m => m.Especialidade)   // Medico ->  Especialidade
    .Where(c => c.Data == hoje)
    .OrderBy(c => c.Horario)
    .ToListAsync();

// Na View, sem nenhuma ida extra ao banco:
// @consulta.Paciente!.Nome, @consulta.Medico!.Especialidade!.Nome
Takeaway

O ThenInclude pertence ao Include imediatamente anterior. Para incluir outro ramo a partir da raiz, comece um Include novo, e não encadeie mais um ThenInclude.

Trazer só o necessário: Select e AsNoTracking [4]

O Include traz a entidade inteira, com todas as colunas. Para uma tela que mostra quatro campos, a projeção com Select monta o SELECT exato e dispensa o Include.

var agenda = await _context.Consultas
    .Where(c => c.Data == hoje)
    .OrderBy(c => c.Horario)
    .Select(c => new AgendaItemViewModel
    {
        Horario       = c.Horario,
        Paciente      = c.Paciente!.Nome,           // o JOIN sai daqui,
        Medico        = c.Medico!.Nome,             // sem nenhum Include
        Especialidade = c.Medico!.Especialidade!.Nome
    })
    .AsNoTracking()
    .ToListAsync();
Takeaway

AsNoTracking desliga o rastreador de mudanças: use em toda listagem que só exibe. Nunca use quando você pretende alterar e salvar o objeto carregado, porque o SaveChangesAsync não terá o que gravar.

Agregações: quantas consultas por especialidade

A direção da clínica quer um número, não uma lista. GroupBy com Count vira GROUP BY no MySQL, e o que trafega são cinco linhas, não cinco mil.

var relatorio = await _context.Consultas
    .GroupBy(c => c.Medico!.Especialidade!.Nome)
    .Select(g => new RelatorioItemViewModel
    {
        Especialidade = g.Key,
        Total         = g.Count()
    })
    .OrderByDescending(item => item.Total)
    .ToListAsync();

Confira sempre o log: se o GROUP BY não aparecer no SQL, o agrupamento foi feito em memória, o que significa que a tabela inteira veio para a aplicação antes de ser contada.

Quiz de fixação

Para trazer cada consulta já acompanhada do paciente e do médico em um único acesso ao banco, o que se usa?
  • A Um laço sobre as consultas, buscando o paciente e o médico de cada uma em acessos separados ao banco.
  • BInclude das propriedades de navegação na própria consulta LINQ, que gera uma única ida ao banco.
  • CTrês consultas ao banco, uma por entidade, unidas depois em memória com Select sobre as listas.
  • DAsNoTracking sozinho, que ao dispensar o rastreamento já traz junto os dados relacionados.
