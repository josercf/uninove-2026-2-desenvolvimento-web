CSS Grid: uma grade de linhas e colunas [1]

O Flexbox distribui itens ao longo de um eixo. O Grid desenha uma grade inteira, com colunas e linhas ao mesmo tempo, e encaixa os itens nela. Você declara a grade no contêiner; os filhos não precisam saber de nada.

Takeaway

No Grid, o layout mora no contêiner. Trocar de três para uma coluna é mudar uma única declaração, não reescrever o HTML.

05 CSS Grid, a grade
5

Declarando a grade das especialidades [1]

A mesma lista de especialidades que na Aula 04 virou uma fileira de Flexbox agora vira uma grade de verdade, com controle sobre linhas e colunas.

.lista-especialidades {
  display: grid;
  grid-template-columns: repeat(3, 1fr);  /* três colunas iguais */
  grid-template-rows: auto auto;          /* duas linhas pelo conteúdo */
  gap: 20px;                              /* entre linhas e colunas */
}

/* A grade que se adapta sozinha, ainda sem nenhuma media query */
.lista-especialidades {
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
}
Takeaway

Com auto-fit e minmax, o navegador calcula quantas colunas cabem. Media query só entra quando o layout precisa mudar de forma, não só de tamanho.

Nomeando as regiões com grid-template-areas [1]

.pagina {
  display: grid;
  grid-template-columns: 220px 1fr;
  grid-template-areas:
    "cabecalho cabecalho"
    "menu      conteudo"
    "rodape    rodape";
  gap: 16px;
}

header { grid-area: cabecalho; }
nav    { grid-area: menu; }
main   { grid-area: conteudo; }
footer { grid-area: rodape; }
Takeaway

O desenho da página fica legível dentro do próprio CSS. Reorganizar o layout no celular é reescrever as aspas, uma região por linha.

Grid contra Flexbox: o critério de escolha [1]

Não é rivalidade e não há um vencedor: os dois convivem no mesmo projeto. A pergunta que decide é quantas dimensões o alinhamento precisa controlar.

Como decidir

Se você consegue descrever o alinhamento em uma frase com uma só direção, use Flexbox. Se precisa dizer "esta coluna e esta linha" na mesma frase, use Grid.

Mobile first: o formulário em três larguras [2]

Mobile first é escrever primeiro o layout mais simples, o de uma coluna, e ir acrescentando colunas conforme a tela cresce, com min-width. O caminho contrário obriga a desfazer regra a regra.

Takeaway

Mobile first usa min-width e só acrescenta. A ordem importa: a media query precisa vir depois da regra base, senão a cascata desfaz o que ela acabou de declarar.

05 Media queries e mobile first

Exercício curto: a media query dos cards

Cinco minutos, no seu próprio site.css

  1. Os cards de especialidade estão em três colunas. Escreva a regra que os deixa em uma coluna abaixo de 640 pixels.
  2. Faça isso na ordem mobile first: a regra base é a de uma coluna, e a media query acrescenta as três.
  3. Confira no modo responsivo do DevTools, arrastando a largura até cruzar os 640 pixels.
.lista-especialidades {                    /* base: o celular */
  display: grid;
  grid-template-columns: 1fr;
  gap: 20px;
}

@media (min-width: 640px) {          /* daqui para cima, três colunas */
  .lista-especialidades { grid-template-columns: repeat(3, 1fr); }
}

Pseudo-classes, pseudo-elementos e transições [1]

.card-especialidade { transition: transform 0.2s ease, box-shadow 0.2s ease; }
.card-especialidade:hover { transform: translateY(-4px); box-shadow: 0 6px 16px rgba(0,0,0,.15); }

input:focus, select:focus { outline: 3px solid #C84B31; }   /* onde estou digitando */
.agenda tr:nth-child(even) { background: #F5F5F5; }         /* zebra na tabela */
label.obrigatorio::after { content: " *"; color: #C84B31; } /* marca visual do required */

Pseudo-classe: um estado

:hover, :focus e :nth-child selecionam o elemento em uma situação. :focus não é enfeite: é como quem navega por teclado sabe onde está.

Pseudo-elemento: um pedaço

::before e ::after criam conteúdo decorativo sem sujar o HTML. Nada essencial pode morar ali, porque não é texto real da página.

Transição: o tempo

transition interpola a mudança em vez de saltar. Entre 0,15s e 0,3s a interface parece responsiva; acima disso, parece lenta.

O formulário: action, method e o envio [3]

O form é o primeiro ponto do semestre em que o navegador manda dados de volta para o servidor. O action diz para onde vão; o method diz como.

<form action="/agendamento" method="post">
  <label for="nome">Nome completo</label>
  <input type="text" id="nome" name="nome" required>
  <button type="submit">Agendar consulta</button>
</form>

method="get"

Os dados viajam na própria URL, depois do ?. Ficam no histórico e no favorito. Serve para buscar: filtrar a agenda por especialidade, por exemplo.

method="post"

Os dados viajam no corpo da requisição, fora da URL. Serve para alterar o estado do sistema: criar a consulta, cadastrar o paciente.

Takeaway

Só o que tem name é enviado. Um campo lindo, validado e sem name simplesmente não chega ao servidor.

Os campos que o HTML já oferece prontos [3]

Escolher o tipo certo não é detalhe: é ganhar de graça o teclado adequado no celular, o seletor de calendário e a validação do navegador.

text

Texto livre de uma linha. O padrão quando nada mais serve.

email

Exige o formato de e-mail e abre o teclado com arroba.

tel

Abre o teclado numérico. O formato quem define é o pattern.

date

Calendário nativo. Aceita min e max.

time

Relógio nativo, para o horário da consulta.

number

Quantidade, com min, max e step.

select

Lista fechada de opções conhecidas, como a especialidade.

textarea

Texto longo e livre, como as observações do paciente.

radio

Uma escolha entre poucas, todas visíveis. Mesmo name.

checkbox

Ligado ou desligado, como o aceite do termo.

O label ligado por for é acessibilidade [4]

O for do label aponta para o id do campo. Sem essa ligação, o leitor de tela anuncia "caixa de edição" e o paciente cego não sabe o que digitar ali.

<fieldset>
  <legend>Dados do paciente</legend>

  <label for="cpf">CPF</label>
  <input type="text" id="cpf" name="cpf" placeholder="000.000.000-00" required>
</fieldset>

Leitor de tela

Com o for, o campo é anunciado pelo nome: "CPF, caixa de edição, obrigatório".

Área de clique maior

Clicar no texto do rótulo coloca o cursor no campo. Isso vale para todo mundo, no celular principalmente.

fieldset e legend

Agrupam campos que pertencem ao mesmo assunto e dão um título ao grupo: dados do paciente, dados da consulta.

Validação nativa: o navegador barra antes de enviar [3]

São atributos no HTML, sem uma linha de JavaScript: o navegador bloqueia o envio, foca o campo e escreve a mensagem sozinho.

AtributoNo formulário da clínicaO que o navegador faz
required<input id="nome" required>Recusa o envio com o campo vazio
patternpattern="\d{3}\.\d{3}\.\d{3}-\d{2}"Exige o CPF com pontos e traço
min e maxtype="date" min="2026-09-01"Recusa consulta em data passada
minlengthminlength="5"Cobra um nome com 5 letras ou mais
maxlengthmaxlength="300"Limita o texto a 300 caracteres

Isso não substitui a validação no servidor. Tudo o que está no HTML pode ser desligado no DevTools. Na Aula 09 a mesma regra volta em C#, e é lá que ela passa a valer.

Quiz de fixação

O que o atributo required em um <input> faz?
  • A Faz o campo ser enviado ao servidor mesmo vazio, para que a action receba a propriedade preenchida com nulo.
  • B Impede o envio do formulário enquanto o campo estiver vazio, pela validação nativa que o próprio navegador executa.
  • C Garante que o dado também será validado no servidor, dispensando qualquer verificação adicional na action.
  • DFormata automaticamente o conteúdo digitado no campo, conforme o tipo declarado no atributo type.
