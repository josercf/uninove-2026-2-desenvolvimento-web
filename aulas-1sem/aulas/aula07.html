O que é o .NET: SDK e runtime [3]

O .NET é uma plataforma: linguagem, compilador, bibliotecas e um ambiente de execução. A distinção que confunde todo mundo na primeira instalação é entre o SDK, com que se desenvolve, e o runtime, com que se executa.

Takeaway

Na sua máquina instale o SDK, que já traz o runtime dentro. Runtime sozinho é para servidor: ele executa o que alguém compilou, mas não compila nada.

Versão LTS e a CLI dotnet [3]

O .NET ganha uma versão maior por ano, sempre em novembro. As versões de número par são LTS, com suporte longo; as ímpares são STS, com janela de suporte mais curta.

Por que LTS importa

  • Correções de segurança garantidas por três anos.
  • É o que uma empresa escolhe para um sistema que vai durar.
  • O .NET 10 é LTS: saiu em novembro de 2025 e tem suporte até novembro de 2028.

A CLI: conversar com o .NET pelo terminal

dotnet --version     # a versão do SDK em uso
dotnet --list-sdks   # todos os SDKs instalados
dotnet --info        # SDKs, runtimes e a máquina

Nesta disciplina usamos o .NET 10 LTS. O projeto da Clínica Vida+ vai declarar net10.0 no arquivo .csproj, e é essa versão que precisa aparecer no seu dotnet --list-sdks antes do laboratório de hoje.

C# contra JavaScript: tipagem estática [1]

A diferença que você sente na primeira hora não é a sintaxe: é quando o erro aparece. No JavaScript, ao rodar, na frente do paciente. No C#, ao compilar, na sua tela.

JavaScript, tipagem dinâmica

let idade = 34;
idade = "trinta e quatro";   // aceito

const total = "10" + 5;      // "105"

O tipo pertence ao valor e muda a qualquer momento. O erro só aparece quando aquela linha executa.

C#, tipagem estática

int idade = 34;
idade = "trinta e quatro";   // erro CS0029

int total = "10" + 5;        // nem compila

O tipo pertence à variável e é conferido na compilação. O erro aparece antes de o programa existir.

Takeaway

Tipagem estática é o compilador lendo o seu código antes do usuário. Em troca de declarar o tipo, você recebe erro cedo e um editor que sabe o que cada variável é.

Tipos, var e conversões [1]

Os tipos que a Clínica Vida+ usa o semestre inteiro, e a regra de ouro da entrada de dados: tudo o que chega do teclado é texto.

string nome = "Ana Souza";                  // texto
int idade = 34;                             // inteiro
decimal valorConsulta = 180.00m;            // dinheiro: decimal, nunca double
bool confirmada = true;                     // verdadeiro ou falso
DateTime dataConsulta = new DateTime(2026, 9, 16, 14, 30, 0);

var especialidade = "Cardiologia";          // var: o compilador infere string

string digitado = Console.ReadLine() ?? ""; // do teclado sempre vem texto
if (int.TryParse(digitado, out int minutos))
    Console.WriteLine($"Consulta de {minutos} minutos.");
else
    Console.WriteLine("Digite um número inteiro de minutos.");

var não é o let do JavaScript. Ele não abre mão do tipo: só evita repeti-lo, porque o compilador já o deduziu do valor. A variável continua sendo string para sempre.

Interpolação de strings e o console [1]

O $ antes das aspas liga a interpolação: o que estiver entre chaves é avaliado e colocado no lugar. É o equivalente exato das crases que você usou no JavaScript da Aula 06.

Entrada, saída e interpolação

Console.Write("Nome do paciente: ");
string paciente = Console.ReadLine() ?? "";

string especialidade = "Cardiologia";
string horario = "14:30";

Console.WriteLine(
    $"{horario} | {paciente} | {especialidade}");

No terminal

Nome do paciente: Ana Souza
14:30 | Ana Souza | Cardiologia

Write não quebra a linha, e por isso o cursor fica ao lado da pergunta. WriteLine quebra.

Concatenar com + ainda funciona, mas some no meio das aspas e dos espaços. Interpolação é o padrão do C# moderno. Já o ?? "" está ali porque ReadLine pode devolver nulo quando não há mais entrada: ele troca o nulo por texto vazio e cala o aviso do compilador.

Demonstração: a idade do paciente

Primeiro programa da disciplina em C#. dotnet new console -n Idade, escrever o Program.cs e dotnet run.

Console.Write("Data de nascimento do paciente (dd/MM/yyyy): ");
DateTime nascimento = DateTime.Parse(Console.ReadLine() ?? "");

int idade = DateTime.Today.Year - nascimento.Year;
if (nascimento.Date > DateTime.Today.AddYears(-idade))
    idade--;                       // ainda não fez aniversário este ano

Console.WriteLine($"O paciente tem {idade} anos.");

A subtração de anos sozinha erra em um ano inteiro para quem ainda não fez aniversário: em setembro, quem nasceu em dezembro tem um ano a menos do que a conta diz. O if corrige isso. Regra de negócio é exatamente isto, e é dela que o Módulo 2 trata.

Projeto, solução e o arquivo .csproj [3]

O projeto é uma unidade que compila em um único resultado, e o .csproj é a carteira de identidade dele. A solução, o .sln, apenas agrupa vários projetos; a Clínica Vida+ tem um projeto só.

ClinicaVida.Web.csproj

<Project Sdk="Microsoft.NET.Sdk.Web">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
</Project>

O que cada linha diz

  • Sdk="...Web": é um projeto web, com o ASP.NET Core junto.
  • TargetFramework: compila para o .NET 10.
  • ImplicitUsings: os using mais comuns já vêm ligados.
  • Os pacotes NuGet do projeto também moram aqui.

Não existe lista de arquivos no .csproj. Todo .cs dentro da pasta entra na compilação automaticamente. Criar um arquivo novo é só criar o arquivo.

07 Projeto, solução e csproj

Pacotes NuGet: código que você não escreve [3]

O NuGet é o repositório de bibliotecas do .NET, o equivalente ao npm do mundo JavaScript. Adicionar um pacote escreve uma linha no .csproj e baixa a biblioteca.

dotnet add package Pomelo.EntityFrameworkCore.MySql   # o que usaremos na Aula 11

dotnet list package     # o que já está no projeto
dotnet restore          # baixa tudo o que o .csproj declara

Como isso aparece no projeto

<ItemGroup>
  <PackageReference
     Include="Pomelo.EntityFrameworkCore.MySql"
     Version="..." />
</ItemGroup>

Por que isso é versionado

O .csproj vai para o Git; as bibliotecas baixadas, não. Quem clonar o seu repositório roda dotnet restore e recebe exatamente os mesmos pacotes. É o mesmo princípio do package.json.

O editor: VS Code ou Visual Studio

Os dois servem, e o projeto é o mesmo arquivo em disco nos dois casos. A escolha é de conforto, não de compatibilidade.

VS Code com o C# Dev Kit

Leve, roda em Windows, macOS e Linux, e é o mesmo editor que você já usa desde a Aula 03. Instale a extensão C# Dev Kit para ter IntelliSense e depuração.

Visual Studio

Só Windows, mais pesado, com depurador e ferramentas visuais mais completas. A edição Community é gratuita para uso acadêmico.

O terminal em qualquer um

Todos os comandos da disciplina são de CLI. Editor bonito ajuda, mas quem cria, compila e executa é o dotnet.

Em sala usaremos o VS Code. Se você preferir o Visual Studio, tudo funciona igual: os comandos do laboratório rodam no terminal integrado dos dois.

Os quatro comandos do dia a dia [3]

São estes quatro que você vai digitar até dezembro. Vale decorar o que cada um faz, porque o erro comum é usar um esperando o efeito do outro.

ComandoO que faz
dotnet new mvc -n NomeCria um projeto novo a partir de um modelo. O -n dá o nome do projeto e da pasta
dotnet buildCompila o projeto e aponta os erros. Não executa nada
dotnet runCompila e executa. Alterou o código, precisa parar e rodar de novo
dotnet watch runExecuta e fica observando os arquivos: salvou, ele recompila e atualiza sozinho

No laboratório de hoje usaremos o dotnet watch run, para editar a página da clínica e ver o resultado no navegador sem parar e subir a aplicação a cada mudança. Para encerrar, Ctrl+C no terminal.

Os dois arquivos que mandam no projeto [2]

Program.cs, o ponto de entrada

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllersWithViews();

var app = builder.Build();
app.UseStaticFiles();      // serve o wwwroot

app.MapControllerRoute("default",
  "{controller=Home}/{action=Index}/{id?}");

app.Run();

A última linha coloca o servidor no ar. Aquela rota é o assunto da Aula 08.

appsettings.json, a configuração

{
  "Logging": {
    "LogLevel": {
      "Default": "Information"
    }
  },
  "AllowedHosts": "*"
}

É aqui que, na Aula 11, entra a chave ConnectionStrings com o endereço do banco clinicavida. Configuração fica fora do código.

Takeaway

Ao abrir um projeto ASP.NET Core que você nunca viu, comece pelo Program.cs: ele mostra, em vinte linhas, tudo o que a aplicação sabe fazer.

Quiz de fixação

Qual comando cria um novo projeto ASP.NET Core MVC chamado ClinicaVida.Web?
  • Adotnet build mvc ClinicaVida.Web, que compila o projeto a partir do modelo MVC e o deixa pronto para execução.
  • Bdotnet add mvc ClinicaVida.Web, que acrescenta o modelo MVC a um projeto vazio criado anteriormente.
  • Cdotnet run mvc ClinicaVida.Web, que gera o projeto a partir do modelo MVC e já o executa no servidor local.
  • Ddotnet new mvc -n ClinicaVida.Web, que gera a estrutura completa do projeto a partir do modelo MVC.

Laboratório, passo 4 de 6: o .gitignore do .NET

Compilar gera as pastas bin/ e obj/, com centenas de arquivos binários que não vão para o Git: eles são recriados a cada build e só poluem o histórico.

cd ..                       # de volta à raiz do fork
dotnet new gitignore        # gera o .gitignore oficial do .NET

git status                  # bin/ e obj/ não podem mais aparecer

Se bin/ ou obj/ já tiverem sido adicionados antes do .gitignore, o Git continua rastreando os dois. Remova do índice sem apagar do disco: git rm -r --cached ClinicaVida.Web/bin ClinicaVida.Web/obj

Entregável de hoje, commit e push

  • O projeto ClinicaVida.Web, executando localmente.
