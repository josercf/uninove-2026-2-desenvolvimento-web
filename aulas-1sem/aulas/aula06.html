De onde viemos: o formulário da Aula 05

Você entregou o agendamento.html responsivo, com Grid, media queries, o formulário completo e a validação nativa ligada. Ela funciona, e hoje descobrimos onde ela para.

O que a validação nativa resolve

  • required: o campo não pode ficar vazio.
  • type="email": o texto precisa parecer um e-mail.
  • minlength e pattern: formato do texto.
  • Tudo isso sem uma linha de código escrita por você.

O que ela não sabe dizer

  • Que a data da consulta precisa estar no futuro.
  • Que o horário precisa cair dentro do expediente da clínica.
  • Que o CPF digitado tem que somar 11 dígitos de verdade.
  • Como responder ao paciente sem recarregar a página.

O limite é conceitual: o HTML descreve a forma do dado. Regra de negócio é comportamento, e comportamento no navegador tem um nome só: JavaScript.

Onde o JavaScript roda e como ele chega à página [4]

O JavaScript é executado dentro do navegador do paciente, na máquina dele, não no servidor da clínica. O navegador lê o HTML de cima para baixo, e onde ele encontra um <script> ele para para executar. O atributo defer é o que evita essa parada.

<!-- em agendamento.html, no fim do head: o script espera o HTML terminar -->
<script src="assets/js/agendamento.js" defer></script>

Variáveis: const por padrão, let quando muda [1]

A pergunta certa não é "qual usar", é "isto vai ser reatribuído?". Se não vai, use const.

const NOME_DA_CLINICA = 'Clínica Vida+';   // nunca muda: const
let pacientesNaFila = 3;                   // muda ao longo do dia: let
pacientesNaFila = pacientesNaFila + 1;     // agora vale 4

const especialidades = ['Cardiologia', 'Pediatria'];
especialidades.push('Ortopedia');          // permitido: o array continua o mesmo
// especialidades = [];                    // erro: isto seria reatribuir a const

E o var? Existe, você vai encontrar em código antigo, e vaza para fora do bloco em que foi declarado, o que produz bug difícil de achar. let e const respeitam as chaves. Nesta disciplina, não usamos var.

Tipos, typeof e por que === e nunca == [1]

Todo valor lido de um campo de formulário chega como texto, mesmo que o campo seja type="number". É aí que a comparação frouxa cobra o preço.

typeof 'Ana Souza'     // 'string'      typeof 42          // 'number'
typeof true            // 'boolean'     typeof undefined   // 'undefined'

const idade = campoIdade.value;   // '18', com aspas: veio de um input

idade == 18           // true  ... o == converte o tipo antes de comparar
idade === 18          // false ... o === compara valor E tipo
Number(idade) === 18  // true  ... você converte, de propósito, e sabe disso
Takeaway

Use sempre === e !==. A conversão automática do == segue regras que ninguém memoriza, e o bug que ela produz aparece meses depois, em produção.

Condicionais e laços [1]

A clínica atende das 07h às 19h. Essa frase é regra de negócio, e vira condicional.

const hora = 8;

if (hora < 7 || hora >= 19) {
  console.log('Fora do expediente da Clínica Vida+');
} else {
  console.log('Dentro do expediente');
}

const especialidades = ['Cardiologia', 'Pediatria', 'Ortopedia'];

for (const nome of especialidades) {   // percorre os VALORES do array
  console.log(nome);
}

Existem também o for clássico e o while. Para percorrer array, prefira for...of.

Funções: dar nome a uma regra da clínica [1]

Uma função embrulha uma decisão e lhe dá um nome. Depois disso, a regra é lida e testada em um lugar só.

function calcularIdade(dataNascimento) {
  const hoje = new Date();
  return hoje.getFullYear() - dataNascimento.getFullYear();
}

const dentroDoExpediente = (hora) => hora >= 7 && hora < 19;

console.log(calcularIdade(new Date(1990, 4, 12)));   // 36
console.log(dentroDoExpediente(8));                  // true

Função declarada

Começa com function e tem nome próprio. Boa para regras com várias linhas, como calcularIdade.

Função de seta

A sintaxe (x) => ..., curta, guardada em uma const. Sem chaves, o valor da expressão já é o retorno.

Arrays: push, filter, map e find [1]

O corpo clínico da Vida+ é uma lista de objetos. Quase tudo que a recepção pede é uma dessas quatro operações.

const medicos = [
  { nome: 'Dra. Helena Prado', crm: '34211', especialidade: 'Cardiologia' },
  { nome: 'Dr. Caio Nunes',    crm: '41880', especialidade: 'Pediatria'   },
  { nome: 'Dra. Marta Lisboa', crm: '55307', especialidade: 'Cardiologia' },
];

medicos.push({ nome: 'Dr. Ivo Reis', crm: '60912', especialidade: 'Ortopedia' });

medicos.filter((m) => m.especialidade === 'Cardiologia');  // um array com 2
medicos.map((m) => m.nome);                                // um array de nomes
medicos.find((m) => m.crm === '41880');                    // 1 objeto ou undefined
Takeaway

filter devolve vários, find devolve um só, map devolve outra coisa com o mesmo tamanho. Nenhum dos três altera o array original; só o push altera.

Template literals e o console como ferramenta

Crase no lugar de aspas, e ${...} para injetar valor no meio do texto. O console não é enfeite: é onde você descobre o que o seu código realmente fez.

const paciente = 'Ana Souza';
const especialidade = 'Cardiologia';

console.log(`Consulta de ${paciente} em ${especialidade}`);
console.table(medicos);            // lista de objetos em formato de tabela
console.error('CPF inválido');     // destacado em vermelho no console

Abra o console agora: F12 ou Ctrl+Shift+I, aba Console. Nele você digita JavaScript direto na página aberta, sem editar arquivo nenhum. É o laboratório mais rápido que existe para testar uma ideia.

O DOM: o seu HTML virado árvore de objetos [2]

Ao ler o agendamento.html, o navegador não guarda texto: ele constrói uma árvore de objetos vivos. Mexer nessa árvore muda a tela na hora, sem recarregar nada.

Takeaway

O arquivo .html é lido uma vez, no carregamento. Depois disso, o que existe é o DOM, e é ele que o seu JavaScript altera. Por isso a tela muda sem o arquivo mudar, e por isso tudo volta ao original quando a página recarrega.

Selecionar um nó e ler ou escrever nele [2]

O seletor é o mesmo que você já escreve em CSS desde a Aula 04. O que muda é que agora ele devolve um objeto para o seu código manipular.

const form  = document.querySelector('#form-agendamento');   // o primeiro que casa
const cpf   = document.querySelector('#cpf');
const cards = document.querySelectorAll('.lista-especialidades li'); // TODOS que casam

cpf.value;                       // lê o que o paciente digitou no campo
cpf.value = '';                  // escreve, e a tela muda na hora
document.querySelector('h1').textContent = 'Clínica Vida+ | Agenda';
cpf.setAttribute('aria-invalid', 'true');   // atributos também são acessíveis

querySelector

Devolve um elemento só, o primeiro que casa, ou null se nenhum casar. É o que você usa com id.

querySelectorAll

Devolve uma lista, com length e forEach. Lista vazia quando nada casa, nunca null.

classList: o JavaScript manda, o CSS desenha [2]

Não escreva estilo no JavaScript. Declare a aparência no CSS, como você já fez nas Aulas 04 e 05, e deixe o JavaScript apenas ligar e desligar a classe.

/* em assets/css/site.css, escrito uma vez */
.oculto { display: none; }
.campo-invalido { border-color: #C84B31; }
const avisoCpf = document.querySelector('#aviso-cpf');

avisoCpf.classList.add('campo-invalido');       // marca o erro
avisoCpf.classList.remove('campo-invalido');    // desfaz a marcação
avisoCpf.classList.toggle('oculto');            // inverte o estado atual
avisoCpf.classList.toggle('oculto', escondido); // liga ou desliga por condição
Takeaway

Separação de responsabilidades: HTML descreve o conteúdo, CSS descreve a aparência, JavaScript decide quando cada aparência vale. Misturar os três no mesmo lugar é o que torna a página impossível de manter.

Eventos: reagir ao que o paciente faz [3]

Você não pergunta ao navegador se algo aconteceu. Você registra um tratador e o navegador o chama quando acontecer.

const form  = document.querySelector('#form-agendamento');
const busca = document.querySelector('#busca-especialidade');

form.addEventListener('submit', (event) => { /* ao enviar o formulário */ });
busca.addEventListener('input', (event) => { /* a cada tecla digitada  */ });
select.addEventListener('change', (event) => { /* ao trocar a opção    */ });
botao.addEventListener('click', (event) => { /* ao clicar             */ });

click

Botão pressionado. O mais comum de todos.

input

Dispara a cada tecla. É o do filtro de busca.

change

O valor mudou e o campo perdeu o foco. É o do select.

submit

Do form, não do botão. É o evento de hoje.

O objeto event e o preventDefault() [3]

Todo tratador recebe um objeto event, com o que aconteceu e quem disparou. Nele está o método que muda tudo no submit.

form.addEventListener('submit', (event) => {
  event.preventDefault();   // sem esta linha, a página recarrega e o resto se perde
  console.log('quem disparou:', event.target.id);
});

Quiz de fixação

Para que serve event.preventDefault() dentro do tratador do evento submit de um formulário?
  • A Impede o comportamento padrão do navegador, que é enviar o formulário e recarregar a página, deixando o controle com o código JavaScript.
  • B Limpa todos os campos do formulário, devolvendo cada um ao valor que tinha quando a página foi carregada pela primeira vez.
  • CEnvia o formulário por AJAX automaticamente, montando a requisição a partir dos campos declarados dentro do elemento form.
  • D Valida sozinho todos os campos obrigatórios do formulário, exibindo as mensagens de erro que o navegador traz por padrão.

Laboratório, passo 2 de 6: interceptar o submit

Primeiro dê um id ao formulário e a cada campo que o código precisa ler. Sem id, não há como selecionar o nó.

<form id="form-agendamento" action="#" method="post">

Laboratório, passo 3 de 6: o CPF com 11 dígitos

A primeira regra que o HTML não expressa. A mensagem aparece ao lado do campo, não em um alerta.

const cpf = document.querySelector('#cpf');
const avisoCpf = document.querySelector('#aviso-cpf');

function validarCpf(campo, aviso) {
  const digitos = campo.value.replace(/\D/g, '');   // descarta ponto e traço
  const valido = digitos.length === 11;
  aviso.textContent = valido ? '' : 'O CPF precisa ter 11 dígitos.';
  campo.classList.toggle('campo-invalido', !valido);
  return valido;
}

Repare no contrato da função: ela escreve a mensagem e devolve true ou false. As três validações do passo seguinte seguem exatamente esse mesmo contrato.

Laboratório, passo 4 de 6: data futura e expediente

Ciclo 4, sozinho. As duas regras que nenhum atributo do HTML consegue declarar.

function validarData(campo, aviso) {
  const hoje = new Date();
  hoje.setHours(0, 0, 0, 0);
  const escolhida = new Date(`${campo.value}T00:00:00`);   // evita o fuso UTC
  const valida = escolhida > hoje;
  aviso.textContent = valida ? '' : 'A consulta precisa ser em uma data futura.';
  return valida;
}

function validarHorario(campo, aviso) {
  const hora = Number(campo.value.split(':')[0]);
  const valida = hora >= 7 && hora < 19;
  aviso.textContent = valida ? '' : 'A Clínica Vida+ atende das 07h às 19h.';
  return valida;
}

Teste os dois extremos: uma data de ontem e o horário 21h00. Cada mensagem precisa aparecer ao lado do seu campo, com a página parada.

Laboratório, passo 6 de 6: o filtro de especialidades

Na página inicial, um campo de busca que filtra os cards de especialidade enquanto o paciente digita. Aqui o evento é input, não submit.

const busca = document.querySelector('#busca-especialidade');
const cards = document.querySelectorAll('.lista-especialidades li');

busca.addEventListener('input', () => {
  const termo = busca.value.trim().toLowerCase();
  cards.forEach((card) => {
    const nome = card.textContent.toLowerCase();
    card.classList.toggle('oculto', !nome.includes(termo));
  });
});

Campo vazio significa termo vazio, e includes('') é sempre true: todos os cards voltam sozinhos. Regra bem escrita não precisa de caso especial.
